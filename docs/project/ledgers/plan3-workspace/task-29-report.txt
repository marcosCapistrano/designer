The base64 of the token (decodable to the token) is in git's argv for the whole clone or pull. BLOCKER 2: set-secret.sh stdin branch fails on input without a trailing newline (defect in the exact text)
- Brief set-secret.sh (exact), under set -euo pipefail: `if [ -t 0 ]; then read -rs -p "$name: " value; echo; else IFS= read -r value; fi`. `read` returns 1 at end of input without a newline, so set -e exits the script before the "Empty value" check.
- Brief bootstrap.sh line 132 (exact): `if [ -n "${GITHUB_TOKEN:-}" ]; then printf '%s' "$GITHUB_TOKEN" | /opt/hub/ops/hub/set-secret.sh GITHUB_TOKEN; fi`. printf '%s' has no trailing newline, so set-secret.sh exits 1 silently and stores nothing. bootstrap.sh (set -e) then aborts at line 132, after the clone, pnpm install and the Playwright install. Re-running does the same, so the "idempotent and safe to re-run" requirement fails whenever GITHUB_TOKEN is passed.
- Evidence (bash probe mirroring the stdin branch, not the script):
    printf '%s' 'ghp_example' | bash read-probe.sh GITHUB_TOKEN   -> no output, exit=1
    printf '%s\n' 'scrypt:x' | bash read-probe.sh HUB_PASSPHRASE_HASH -> value=[scrypt:x], exit=0
- Suggested fix: `IFS= read -r value || true`. The empty-value check then gives its message on empty input, and the brief's static tests are unaffected. An alternative is changing bootstrap.sh line 132 to printf '%s\n', but the set-secret.sh fix also covers any other no-newline pipe.
