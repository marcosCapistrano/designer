CONCERNS
1. The brief's static-file code does not work with the installed @hono/node-server 2.1.5. serveStatic builds its response with
   c.body(...) BEFORE it awaits onFound, and c.body() does not finalize the context, so c.header() inside onFound writes to
   prepared headers that the already-built response never sees. Result: no Cache-Control header at all (test failed with null,
   and I confirmed with a stand-alone script). Fix used: onFound only records the served path in a WeakMap keyed by the
   Context; a small wrapper middleware around serveStatic sets Cache-Control on the Response that serveStatic returns.
   Header values are exactly as in the brief ('public, max-age=31536000, immutable' for assets, 'no-cache' otherwise).
2. Deviation from the brief's condition p.includes('/assets/'): that test is applied to the absolute file path, so a clientDir
   such as /srv/assets/client would make index.html immutable for a year. The condition is now "first path segment of the
   file relative to clientDir is assets" (same result for the normal layout; covered by the "caches by position" test).
3. Extra behaviours beyond the brief: a non-JSON body to POST /build/messages is 400 'text is required' (not a 500);
   `after` accepts only /^\d+$/ (so '', '-1', '1.5', '1e3' are ignored); task id accepts /^-?\d+$/ so a negative integer reaches
   the service (404 Task not found) while 'x', '1.5', '1e3', '0x10' give 400 'Bad task id'.
4. The static handler has no SPA fallback (unknown non-file paths under / return 404). The brief does not ask for one, and the
   client uses its own route handling, but if the shell uses path-based routes an index.html fallback will be needed in main.ts
   wiring or a later task.
5. Flaky and unrelated: packages/design-model src/perf.test.ts ("median under 150 ms") failed twice under full-repo parallel load

CONCERNS
1. csrf() blocks non-browser callers (curl, scripts) that send a bodyless or form-typed write without Sec-Fetch-Site: same-origin or an
   Origin equal to the request URL's origin (derived from the Host header). Browsers always send Sec-Fetch-Site, so the shell is fine;
   an Origin-only client behind `tailscale serve` depends on the proxy passing the original Host. Not tested here (no main.ts yet);
   worth a smoke test when the hub is wired up behind Tailscale.
2. hono's csrf only inspects form-typed (or missing) content types; a cross-site JSON POST is stopped by the browser's CORS preflight
   (the hub sends no CORS headers), not by csrf(). That is hono's documented behaviour.
3. The M3 behaviour on a vanished app folder during an active run (see above).
