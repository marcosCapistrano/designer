apps/server/src/design/render-files.ts
- EMPTY_MANIFEST = { version: 1, pages: [] } (verbatim from the brief).
- renderDir(dataDir, app) = join(dataDir, 'renders', app).
- renderRoutes({ dataDir, hasApp }): Hono, to be mounted at /api/apps.
  - A use() middleware on /:app/render/* runs first for every render route:
    1. app must match APP_NAME_RE (from @hub/protocol/manifest, the same pattern
       the app manifest schema uses: /^[a-z][a-z0-9-]{0,38}[a-z0-9]$/).
       Failure -> 404 { error: 'Not found' }. hasApp is NOT called.
    2. hasApp(app) false -> 404 { error: 'Unknown app' }.
  - GET /:app/render/manifest.json: the file bytes, or EMPTY_MANIFEST when the
    file is missing. content-type application/json, cache-control no-cache.
  - GET /:app/render/tiles/:key/:tile: key must match /^[0-9a-f]{64}$/ and tile
    must match /^\d+_\d+\.webp$/. Serves tiles/<key>/<tile> as image/webp with
    cache-control "private, max-age=31536000, immutable". Missing -> 404 Not found.
  - GET /:app/render/hitmaps/:file: file must match /^[0-9a-f]{64}\.json$/.
    Serves hitmaps/<file> as application/json, same immutable cache-control.
    Missing -> 404 Not found.
- Paths are built with join() from validated segments only. No resolve(), so an
  absolute segment cannot replace the base. The strict patterns forbid "/", "\",
  "." segments and "%" after decoding.

SELF-REVIEW NOTES
-----------------
- Every URL segment is checked before any fs call: app by APP_NAME_RE, key and
  tile by KEY_RE and TILE_RE, file by HITMAP_RE. Hono's param decoding is
  reflected in the tests: %2F decodes to "/" inside a single segment, so a
  pattern check is needed (the router does not split on it).
- ENOENT, ENOTDIR and EISDIR are treated as "missing". Other read errors are
  rethrown (500).
- No catch-all route was added under /api/apps: a catch-all would shadow routes
  that plan 6 mounts there. Requests that match none of the three shapes (for
  example extra path segments) therefore get Hono's default plain-text 404, not
  the JSON body. Bad segments inside a matched shape always get the JSON body.

CONCERNS
--------
1. Manifest bytes are served as stored. A corrupt (unparsable) manifest.json is
   served as-is, while FsTileStore.readManifest treats it as missing (null). The
   brief says "the file, or EMPTY_MANIFEST when it is missing", so I followed the
   brief. If the controller wants the endpoint to match readManifest, it needs
   JSON.parse and a version check, falling back to EMPTY_MANIFEST.
2. Hono's body Data type is Uint8Array<ArrayBuffer>, so readOrNull copies each
   file into a fresh Uint8Array. This costs one copy per request, which is small
   for webp tiles of 512 px. If large files appear later, use a stream instead.
3. Hit maps use the same cache-control as tiles ("private, max-age=31536000,
   immutable"). The brief only said "immutable". They are hash-named, so this
   seems right, but it is an interpretation.
4. The app-name pattern is APP_NAME_RE from @hub/protocol/manifest; the brief
   named no pattern for app. The middleware returns 404 Not found for a
   malformed name and 404 Unknown app for a well-formed name that hasApp rejects.
5. The brief said "Expected: 7 pass". The file has 11 tests: the 7 brief tests
   plus 4 security tests. All 11 pass.
