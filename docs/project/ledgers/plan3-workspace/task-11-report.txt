Concerns
1. GIT_CONFIG_PARAMETERS is git's internal -c transport format. The single-quoted key=value list has been stable since git 2.31, and the repo runs git 2.43 (verified). A future git could change it; the argv test and the env assertion would catch a regression in either direction.
2. The token-derived header is in the authed git process environment, not argv. It is readable only by the same uid (/proc/<pid>/environ). That satisfies "never in a process argument list" as written.
3. Seeding a bare origin on git 2.43 prints "fatal: expected 'acknowledgments', received 'packfile'" and "warning: push negotiation failed; proceeding anyway with push" to stderr. The push succeeds. Harmless noise, ignored per ruling.
4. The "No I/O in src" convention does not apply literally to git.ts and test-repo.ts, since spawning git and creating temp dirs is their purpose, as the brief requires.
