apps/server/src/auth/sessions.ts
  - SESSION_COOKIE = 'hub_session', SESSION_TTL_MS = 2_592_000_000 (verbatim).
  - SessionStore(db, now = () => Date.now()):
    - create(): randomBytes(32) as base64url. Stores sha256(token) hex with
      created_at and expires_at = created + TTL. Returns the raw token.
    - valid(token): false for undefined. Otherwise true only when a row with
      that token_hash has expires_at > now().
    - revoke(token): deletes the row for sha256(token).
    - purgeExpired(): deletes rows with expires_at <= now(), returns the count.
  - readCookie(header, name): splits on ';', returns the trimmed value of the
    first matching name, undefined for a missing name or an undefined header.
  - requireAuth(sessions): createMiddleware from hono/factory. Reads the
    hub_session cookie. Without a valid session it returns 401
    { error: 'Not logged in' }. Otherwise it calls next().

  - AuthDeps { sessions, limiter, passphraseHash, now? } and authRoutes(deps): Hono.
  - POST /login, checked in this order:
    1. limiter.blocked(now()) → 429 { error: 'Too many attempts. Try again in 15 minutes.' }.
       Returns here. Neither the body nor verifyPassphrase is read, and fail() is not called.
    2. Body is not JSON, or passphrase is not a string → 400 { error: 'passphrase is required' }.
    3. verifyPassphrase fails → limiter.fail(now) → 401 { error: 'Wrong passphrase' }.
    4. Success → limiter.reset(), setCookie(hub_session, sessions.create(),
       { httpOnly, secure, sameSite: 'Strict', path: '/', maxAge: 2_592_000 }) → 204.
  - POST /logout: revokes the cookie's token if present, deleteCookie(path '/') → 204.
  - GET /session: 200 { ok: true } with a valid cookie, else 401 { error: 'Not logged in' }.

1. FIX 1 (important): concurrent wrong logins bypassed the lock
---------------------------------------------------------------
Cause: the first limiter.blocked() check ran before `await readPassphrase(c)`. Requests
that passed that check before any failure was recorded all went on to verifyPassphrase,
so 8 concurrent wrong logins all got 401 (verified bypass).

Change: POST /login now runs
  1. blocked(now()) → 429 (before the body is read; unchanged brief step 1)
  2. await readPassphrase(c)
  3. at = now(); blocked(at) → 429 (new re-check after the body read)
  4. 400 when the passphrase is missing, then verify → fail(at) → 401, or reset() → cookie → 204
From step 3 through fail() or reset() there is no await. verifyPassphrase and
sessions.create are synchronous, so no other request can interleave.
The first check (step 1) stays because the brief pins it as step 1.
