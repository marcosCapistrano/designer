  send that is still preparing git. release() deletes the entry and then resolves `ended`.

CONCERNS
1. state() cost: every state() call while a review task's CI is 'pending' and the app is idle makes two GitHub requests
   (getPr + checkStatus). If the client polls state() frequently, that is rate-limit pressure; there is no throttle
   (the ruling did not ask for one). A short per-task cooldown would be a cheap follow-up.
2. A task created by a send whose createBranchFrom fails is left `failed` with a branch name that does not exist locally
   (brief behaviour). The next send continues that open (failed) task, fails on checkout with 409 'Git: ...' until the user
   closes the task. Close works on failed tasks, so it is recoverable from the UI, but it is a sticky state.
3. Stop during `pushing`: git push is not cancellable (finishTask passes no signal to repo.push), so the push completes,
   the PR is opened and the task ends `review`, not `failed`. Not stuck, but "Stopped by you." only applies to working and
   verifying. Likewise a stop in the window after Claude finishes and before finishTask only takes effect if a build
   command runs (no signal check before pushing when there are no commands).
4. Small deviations from the brief's wording (all behaviour-compatible with its tests):
   - one `runs` map instead of two maps; idle waits on a promise created at reservation (covers git preparation);
   - recover() skips an app that is currently running (the brief says every task in working/verifying/pushing); a fresh
     service at startup behaves exactly as specified;
   - retryQueued checks out the task branch BEFORE adding the 'Retrying after the usage limit.' status message, so a
     failed checkout does not leave a misleading "Retrying" line; a checkout failure marks the task failed with
     'Git: <msg>' (otherwise it would be retried on every tick) and is not counted; one task's failure does not stop the others;
   - when a send fails after creating a task, its error is 'Git: <msg>' (the same text as the 409) and an error message with the same text is added to the feed
     (corrected in fix round 1: the first version of this report said nothing was added; abandon()/failTask always adds an error message);
   - recover()/failures publish the changed task over the hub.
5. Tests make a real git repo each (45 tests, about 38 s for the file). The stderr lines "fatal: expected 'acknowledgments',
   received 'packfile'" come from makeTestRepo's seed push in this sandbox; they are harmless and pre-existing.

2. CI refresh single-flight (service.ts).
   - refreshes: Map<taskId, Promise<void>>. refreshOnce(taskId, needed) is the only way the service reads CI (state() and the
     review-task refresh in send()'s prepare). Concurrent callers for one task share one flight. Inside the flight the stored task is
     re-read and `needed` re-checked (state(): still review and pending), so a task another refresh just brought up to date is not read again.
   - ci.ts pollCi() calls refreshCi internally, so the service cannot wrap it per task. Instead the service orders polls and flights:
     pollCi() waits for the flights in flight (and any earlier poll) before it starts, sets `polling`, and every flight started while
     a poll runs waits for it (then re-checks `needed`). So a poll and a state()/send refresh never read one task at the same time.
   - Tests ('BuildService CI refresh', 4 tests): two concurrent state() plus one pollCi on a green PR -> 'CI passed. Ready to merge.' exactly once;
     with getPr gated: two state() calls share one GitHub read and the poll that waited makes exactly one more (2 reads, not 3), one announcement;
     a state() arriving during a gated poll waits for it and does no read of its own (1 read, 1 announcement);
     a send and a state() share one refresh.
   - Mutation checks (service.ts restored each time): no single-flight fails the shared-read test; flight not waiting for the poll fails 2 tests;

   - Root cause note (for the controller): the duplicate comes from refreshCi in ci.ts reading `task` before its GitHub await and
