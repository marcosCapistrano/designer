SELF-REVIEW NOTES
- SQL and parameters: every value is bound. The one dynamic fragment is the column list in updateTask, which
  comes from PATCH_COLUMNS, a Record<keyof TaskPatch, string>, so the compiler requires every patch key to map to a
  column. Status lists are passed as one bound JSON parameter and read with json_each, so no SQL string is built
  from values.
- updateTask applies only keys whose value is not undefined; null is written, which clears the column. updatedAt is
  always bumped.
- pendingPrompt is not part of the BuildTask DTO. It is written through updateTask and read through pendingPrompt();
  task() does not select it, and a test asserts that.
- messages(): with afterId, the rows with id > afterId are returned ascending up to limit. Without it, the newest
  limit rows are selected by a DESC subquery and returned ascending.
- addMessage returns the object built from the insert result (no re-read); at = now().
- A foreign-key violation (addMessage with an unknown taskId) propagates from SQLite as-is.

CONCERNS
1. The default clock is Date.now (the brief's signature is now?: () => number). This follows the existing pattern in
   apps/client (`opts.now ?? Date.now`). It is the only Date reference in store.ts. It conflicts with the literal
   "no Date in src" convention, so the controller may want a different default source.
2. updateTask throws Error('build task <id> not found') when no row matches. The brief does not specify this case.
   createTask and updateTask re-read the row through task().
