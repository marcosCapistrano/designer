What was implemented
--------------------
- BuildError (status 400 | 404 | 409), exported.
- refreshCi(deps, taskId): returns null for a missing task; returns the stored task unchanged when
  it is not in review, has no prNumber, deps.github is null, or the app / RepoRef cannot be found.
  Reads getPr. Merged -> status merged, mergeSha, "Pull request #n was merged on GitHub.", onMerged
  when mergeSha is set. Closed -> status closed, "Pull request #n was closed.". Otherwise reads
  checkStatus(headSha) and stores {ci, headSha} when either changed (publishTask). A CI state change
  to success posts "CI passed. Ready to merge." (status); to failure posts "CI failed: <names>"
  (error), names = checks whose conclusion is in FAILED_CONCLUSIONS. GitHub errors are caught,
  logged with console.warn (message text only, no token), and the stored task is returned.
- pollCi(deps, isRunning): refreshes every review task whose app is not running, in sequence.
  Poll cap: see Concerns 1.
- mergeTask(deps, app, taskId, running): checks in the brief's order (404, 409 running, merged
  returns it, 409 no open PR, 409 GITHUB_TOKEN, getPr). Merged on GitHub -> recorded as above.
  Closed -> status closed, then 409 "The pull request is closed.". Open -> checkStatus on the
  current head, stores {ci, headSha}, refuses unless success with the brief's message. Then
  github.merge(ref, n, headSha) pinned to that head; a refusal (merged false) -> 409
  "GitHub refused the merge: <message>". On success: status merged, mergeSha, error null,
  "Merged pull request #n.", publishTask, onMerged({app, taskId, prNumber, sha}).

Concerns
--------
1. Poll limit (brief defines none). The brief gives no poll limit or timeout, and pollCi takes no
   interval. I used the Task 21 default ciPollMs = 30 000 ms x 120 attempts = about one hour.
   The rule: a task whose CI stays pending on the same head is checked at most 120 times by
   pollCi (see CI_POLL_LIMIT). The count resets when the stored headSha changes, which Task 16's
   finish does for a new commit. The count is in memory, so a restart gives a fresh 120. A GitHub
   error during a poll counts as a poll when the stored ci is pending (minor).
2. Outcome of the cap. The task stays review with ci 'pending'. The brief defines no timed-out
   outcome or copy, so no status message is posted when polling stops; please decide whether the
   lead wants one. mergeTask still rechecks CI on the current head, so a stopped PR can be merged
   once green. Task 18's on-demand refresh (refreshCi on a state read) is not capped and still calls
   GitHub.
3. CI state 'none' is not capped. The brief only caps pending. A repo with no check runs keeps
   being polled every 30 s per review task. Decide whether 'none' should count too.
4. Copy not in the brief (my choices, please confirm):
   - mergeTask 409 "This app has no GitHub remote." when the app or its origin is not a GitHub
     remote (the brief gives no error for this case).
   - mergeTask's merged-on-GitHub path reuses refreshCi's "Pull request #n was merged on GitHub."
     and its closed path posts "Pull request #n was closed.". The brief specifies no messages there.
5. GitHub errors in mergeTask (getPr or checkStatus failing, or a merge error other than
   405/409, which OctokitGitHub already maps to merged false) propagate as plain errors, not
   BuildError. The brief only specifies the refusal mapping. refreshCi catches its errors. The
   route layer needs to map mergeTask's thrown non-BuildError to a 5xx.
6. In mergeTask, a merge result of merged true with sha null is treated as a refusal. This keeps
   onMerged's sha typed as string without a non-null assertion. OctokitGitHub always returns the
   sha on a successful merge, so this path is not reachable with the real adapter.
7. Commit trailer. The controller's dispatch asked for "Co-Authored-By: Claude Opus 5.5 (1M
   context)". The harness attribution for this session, which constraints.txt says to use, gives
   "Co-Authored-By: Claude Haiku 5.5 <noreply@anthropic.com>", and I am running as Haiku 5.5. I used
   the harness trailer, with the Claude-Session line. If Opus is wanted, the commit needs a
   reword (I did not amend).
8. pollCi overlap. If one poll runs longer than ciPollMs and the timer starts another, the two can
   both increment a task's count, so the cap would arrive sooner (about 30 minutes). Harmless; noted
   for Task 21.
