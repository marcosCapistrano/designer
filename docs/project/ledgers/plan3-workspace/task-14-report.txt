    - branchSlug(prompt, id): first 6 words of the lowercased prompt (non-alphanumerics

    - Types BuildCommandName, BuildCommand, CommandResult, RunCommand; constants
      OUTPUT_TAIL (4000), COMMAND_TIMEOUT_MS (900000).
    - resolveBuildCommands(dir, manifest): a non-null manifest yields install,
      typecheck, test from manifest.build. Otherwise package.json is read (missing or
      unparsable -> []); package manager is pnpm (pnpm-lock.yaml), else yarn (yarn.lock),
      else npm; install is 'pnpm|yarn install --frozen-lockfile', 'npm ci' with
      package-lock.json, else 'npm install'; typecheck when scripts.typecheck is a
      string; test when scripts.test is a string without 'no test specified'.
    - runCommand: spawn('bash', ['-c', cmd]) with env { ...scrubEnv(process.env), CI: '1' },
      detached, stdio ['ignore','pipe','pipe']. stdout and stderr are appended to one
      string, trimmed to the last 4000 characters once it exceeds 8000. Timeout or abort
      sends SIGTERM to the process group (process.kill(-pid)), then SIGKILL after 5 s.
      ok = code === 0 && !timedOut && !aborted. Resolves once, on 'close' (or 'error').

CONCERNS (non-blocking, for the controller)
  1. Brief count mismatch: "Expected: 16 pass" does not match its enumerated cases (25)
     or the implemented suite (27). Every enumerated case is covered.
  2. Choices the brief did not spell out:
     - NotebookEdit reads input.notebook_path (falls back from file_path), its real field.
     - An 'error' event from spawn resolves with code null and the message appended to
       output, so a bad cwd does not crash the caller.
     - A Bash summary without a string command, or a Read/Edit/Write/Grep/Glob call
       without its string field, falls back to the tool name.
     - resolveBuildCommands checks typecheck and test with typeof === 'string', so an
       empty script string still counts as present.
     - Output is trimmed once it exceeds 2 * OUTPUT_TAIL (strictly greater than 8000).
  3. Module I/O: the convention "no I/O in src" cannot apply literally here. The brief
     requires reading package.json and lockfile existence (resolveBuildCommands) and
     spawning processes (runCommand). Both are I/O by design, so I kept them in this
     module as specified. The pure helpers in naming.ts do no I/O.
  4. The 'close' event resolves the command. A background grandchild that keeps stdout
     open after the shell exits holds the result until the timeout kills the group.
     This matches the brief's timeout behaviour.
