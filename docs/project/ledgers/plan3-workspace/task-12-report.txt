1. WHAT WAS IMPLEMENTED

apps/server/src/github/github.ts
  - Types: RepoRef, PrInfo, CheckRun, CiStatus, MergeOutcome, GitHub interface.
  - FAILED_CONCLUSIONS (exact list from the brief).
  - summarizeChecks(runs): [] -> 'none'; any completed run with a failed conclusion
    -> 'failure'; else any run not completed or completed with null conclusion
    -> 'pending'; else 'success'.
  - parseGitHubRemote(url): three anchored patterns (scp-style git@github.com:o/r,
    ssh://git@github.com/o/r, https://[user[:pass]@]github.com/o/r), optional .git
    and trailing slash; anything else -> null.

apps/server/src/github/fake.ts
  - FakeGitHub implements GitHub, exactly per the brief's rules:
    createPr numbering from 1, url https://github.com/<o>/<r>/pull/<n>, headSha
    head-<n>, duplicate open head throws; findOpenPr by headRef + open; getPr
    unknown -> Error('Not Found'); merge checks not-open, then stale sha, then
    merges (mergeSha merged-<n>, pushes to merges).
  - setChecks, movePrHead, markMerged, closePr, autoGreenAfter as specified.
  - calls records the five GitHub-interface method names in call order.

apps/server/src/github/octokit.ts
  - OctokitGitHub(token, fetchFn?) builds
    new Octokit({ auth: token, request: { fetch: fetchFn } }).
  - findOpenPr -> pulls.list({ owner, repo, head: owner:branch, state: 'open', per_page: 1 })
  - createPr -> pulls.create (head, base, title, body)
  - getPr -> pulls.get
  - checkStatus -> checks.listForRef({ ref: sha, per_page: 100 }), state via summarizeChecks
  - merge -> pulls.merge({ merge_method: 'squash', sha }); 405 and 409 errors become
    { merged: false, sha: null, message: err.message }; other errors rethrow.
  - PR mapping: number, html_url, state, merged ?? false, head.sha, head.ref,
    base.ref; mergeSha = merge_commit_sha only when merged, else null.

6. CONCERNS
-----------
  a. Test count. The brief says "Expected: 12 pass". Its bullet list yields 18
     separate cases (summarizeChecks 6, parseGitHubRemote 2, FakeGitHub 3,
     OctokitGitHub 7, which adds findOpenPr-returns-null and a non-405/409 rethrow
     case). All 18 pass. The count in the brief looks like a miscount, not a
     missing behavior.
  b. RequestError is not importable. @octokit/request-error is not a direct
     dependency of apps/server, and pnpm will not resolve it, and I was not allowed
     to change dependencies. The refused-merge check therefore tests
     err.name === 'HttpError' and status 405 or 409. It matches RequestError's
     shape exactly, but it is structural, not an instanceof check.
  c. checkStatus reads one page (per_page 100, as the brief specifies). A commit with
     more than 100 check runs would have its state computed over only the first 100,
     which could report 'success' while later runs fail. The brief does not ask for
     pagination. Flagging it for the controller to decide whether to paginate.
  d. FakeGitHub interpretations where the brief is silent:
     - merge and getPr on an unknown PR number throw Error('Not Found') (the same as
       getPr). merge on an unknown number does not return a not-open outcome.
     - setChecks(sha, []) is an explicit empty result and wins over autoGreenAfter.
     - calls holds only the five GitHub-interface methods. The helper methods
       (setChecks, movePrHead, markMerged, closePr) are not recorded.
     - PRs are keyed by number only, and findOpenPr and the duplicate-head check
       ignore the repo argument. Fine for single-repo tests, but it is not
       multi-repo aware.
     - markMerged does not add an entry to merges, because the merge did not happen
       through the hub.
  e. mergeSha uses the merge_commit_sha-when-merged rule for every PR-returning
     method (createPr, findOpenPr, getPr), not only getPr. For open PRs this is
     always null, so the result is the same as the brief.
