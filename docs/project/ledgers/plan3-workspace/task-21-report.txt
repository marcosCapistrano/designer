DECISIONS AND DEVIATIONS (all small, all deliberate)
==============================================================================
1. HubOptions gained `now?` (required by controller addition 1) and `heartbeatMs?` (mine). heartbeatMs lets
   server.test.ts exercise "session expiry closes the socket on the heartbeat" through the real startHub path with
   an injected clock, without exposing a recheck method on RunningHub. Default 30_000 (attach.ts's HEARTBEAT_MS).
2. close() order: the brief lists stopAll, then ws close, then server.close. I call server.close() first (and await it
   last) so that no new request can start a run after stopAll has taken its snapshot of runs. WebSockets stay up
   through stopAll, so clients still receive the runs' final messages. End state is the brief's.
3. Origin check runs after the path check and before the session check (cheaper, no DB read); the response is
   403 via the same refuse() path as 401. Compared: new URL(origin).host against Host.toLowerCase(), so scheme is
   ignored (hub sees plain http behind tailscale serve). Origin present but unparsable ('null', '') is refused. No
   Origin is allowed.
4. recheck fails closed: an isAuthed that throws during a recheck terminates the socket (same stance as upgrade).
   A transient DB error would therefore drop every socket once; clients reconnect.
5. Sweep order on heartbeat: recheck() then hub.sweep().
6. changeOrigin: NO change to apps/client/vite.config.ts. Fake hub default port 8787 equals the proxy target in
   vite.config.ts (/api and /ws -> http://127.0.0.1:8787). The proxy must keep the default changeOrigin:false.
   Verified empirically (see below): with false the browser's Host (localhost:4173) and Origin
   (http://localhost:4173) still agree at the hub, so csrf's Origin check and the new WebSocket Origin check both
   pass; with changeOrigin:true the Host becomes 127.0.0.1:8787 while Origin stays the page's, so the WebSocket
   upgrade is refused with 403 and a bodyless POST with only Origin gets 403. Task 28 must NOT add changeOrigin.
7. Extra tests beyond the brief's three in server.test.ts (and two extra spawn-based test files) because the
   controller additions (clock injection, startup purge, logout/expiry socket closing, Origin check, crash
   handlers, SIGTERM exit 0) are requirements and are otherwise unobserved. The brief's three are present with
   their exact names.

CONCERNS (informational)
==============================================================================
1. Not verified in a real browser: no Chromium/Playwright browsers exist in this sandbox. The login cookie is
   `Secure`; Chromium and Firefox accept Secure cookies set over http://localhost, but Task 28 should confirm that
   with the first Playwright run (and that its helpers do not use a request context that drops Secure cookies).
2. Task 28: keep the proxy at default changeOrigin (see decision 6); webServer for the fake hub can be
   `pnpm -F @hub/server dev:fake` (HUB_FAKE_PORT unset = 8787 = proxy target). Playwright's SIGKILL of the
   webServer would skip the fake hub's scratch cleanup (SIGTERM/SIGINT clean up).
3. close() does not wait for an in-flight CI-poll or retry tick (they have no abort signal and may be waiting on
   GitHub). A tick that touches the db after db.close() throws inside its own catch, which stays silent once
   close() has begun. A queued-retry tick racing close() could in theory start one run after stopAll's snapshot; the
   window is the length of git preparation and the process is exiting anyway.
4. Other sessions' vite processes are running on this machine (ports 4174 preview, 5199 dev). I did not touch them.
5. A heartbeat or logout recheck that finds isAuthed throwing (db error) drops every socket (fail closed).
