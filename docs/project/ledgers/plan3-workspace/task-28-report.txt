CODE FIX THE TESTS EXPOSED (apps/client/src/areas/build/BuildArea.tsx, commit f98c4bf)
First run: 5 of 6 passed; the Build flow timed out at `build-send` click because the Send button stayed disabled.
Root cause: BuildArea's data effect began with an unconditional reset (setView(EMPTY_VIEW), setDraft(''), setSending(false),
setError(null), ...). Preact runs effects after paint, and flushes a component's pending effects before its next render.
So text entered between the first render and that effect (Playwright fill is that fast; a very fast typist could hit it)
was queued by onInput first and then overwritten by the effect's setDraft(''). The textarea ended empty and Send disabled.
Evidence: a throwaway probe spec (deleted) that filled build-input immediately after opening the app read back "" after
500 ms before the fix and "immediate" after it.
Fix: a stateApp ref records which app the state belongs to; the reset runs only when `app` actually changed
(AppView already keys BuildArea on app, so a mount needs no reset). Nothing else in the effect changed.
No unit test was added for it: client unit tests run in node with no DOM, and the Build flow e2e covers the behavior.
No change to apps/server or to claude/.
