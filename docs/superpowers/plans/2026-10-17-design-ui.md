# Design area UI redesign — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Design tab's chrome with a full-screen canvas, a top bar, a slide-in inspector with real controls, and a chat bottom sheet, on a dark token-based visual system.

**Architecture:** A token file and a small `ui/` control kit (Preact + plain CSS, no new dependencies) underpin new Design-area components: `TopBar`, `ImportSheet`, `inspector/`, `ChatSheet`, `PreviewBanner`, composed by `DesignArea`, which owns selection, revision, proposal, busy flags and toasts. The canvas engine gains `fitAll()` and a camera callback; the API client and server are unchanged. `EditorPanel.tsx` and `ChatPanel.tsx` are removed.

**Tech Stack:** Preact 10, plain CSS with custom properties, vitest (node environment, vnode-walking component tests as in `canvas/FrameMenu.test.ts`), Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-10-17-design-ui-design.md`

## Global Constraints

- No new dependencies. Preact + plain CSS; no Tailwind, no UI library.
- Tokens (exact values): `--bg` #121316, `--surface` #1c1e23, `--surface-2` #262930, `--border` #33363e, `--overlay` rgba(18,19,22,0.82); `--text` #e8eaed, `--text-2` #9aa0a6, `--text-3` #6b7076; `--accent` #4c8dff, `--accent-text` #0b1220, `--danger` #ff6b6b, `--warning` #f2c94c, `--ok` #4cd98a; `--text-s` 13px, `--text-m` 14px, `--text-l` 16px, `--text-xl` 20px; `--s1` 4px, `--s2` 8px, `--s3` 16px, `--s4` 24px, `--s5` 32px (per spec "×2 steps" up to `--s6`: use 4, 8, 16, 24, 32, 48); `--radius` 10px, `--radius-s` 6px, `--touch` 44px.
- Touch targets ≥ 44 px. Hover styles only under `@media (hover: hover)`; focus via `:focus-visible` with a 2 px `--accent` ring.
- Sizes: top bar 56 px; inspector 360 px wide, a bottom sheet below 900 px; chat bar 64 px collapsed, sheet ≤ 60 % height; toasts 4 s success, sticky errors.
- Device rule: every `setStyle` from the inspector uses the device of its segmented control, preset to `selection.device`. Inheritance for display: `tablet` ← `base`, `mobile` ← `tablet` ← `base`.
- Stepper steps: 1 for px/%/vh/vw, 0.125 for rem/em; `parseLength` matches `^-?\d*\.?\d+(px|rem|em|%|vh|vw)$`.
- Each committed control change is one `editDesign` call (linked padding/margin: four ops in one call). Clearing a field sends `value: null`.
- Chat behaviour kept verbatim: merge/de-dupe by id, last 200, `design.message` / `design.status` websocket handling, reload on reconnect, `maxLength` 20,000, Stop.
- Voice is not built: the mic button is disabled with title "Voice coming later".
- Server and `net/api.ts` are unchanged.
- 7 GB machine: run `pnpm -F @hub/client test` alone; iterate with `cd apps/client && npx vitest run <dir>`.
- Commits end with a blank line and `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. No push.

## Decisions beyond the spec

- Component tests use the existing vnode-walking style (`canvas/FrameMenu.test.ts`): render the component function with props and walk the returned tree; hooks-based wrappers are tested through their pure view functions, as `FrameMenuView` is.
- The inspector's section open/closed state is stored under `localStorage` key `hub.inspector.sections` as a JSON object `{ [sectionId]: boolean }`; missing = open.
- Shared `ui/` controls are uncontrolled where possible and emit `onCommit(value)` only on commit (release/blur/Enter/change), never on every keystroke, so the inspector's one-edit-per-commit rule is enforced by the control.
- The Design tab hides the shell header and tab row by a `shell-immersive` class on `.shell` set by `App` when the route is `app` + `design`; the top bar carries back link, app name and area switch instead.

## Review Focus

1. **A value the inspector can't parse** (`auto`, `calc(100% - 8px)`, `var(--space-4)`) in a stepper/color field. Expected: shown verbatim as text, editable, no NaN or crash. Pinned in Task 3 values tests and section tests.
2. **The selection changes while an edit is in flight.** Expected: the response for the old target never writes into the new target's fields. Pinned in Task 3 (`Inspector` keeps a selection token).
3. **A stale revision (409) on an edit** after a chat edit applied elsewhere. Expected: the control reverts, the inline error shows, the selection reloads with the new revision. Pinned in Task 3.
4. **Narrow width (< 900 px) with both inspector and chat open.** Expected: inspector as a bottom sheet, chat bar still reachable, no overlap hiding the send button. Pinned in Task 5 layout test (class assignment) and Task 6 e2e at 834 px.
5. **Preview state and reconnect.** A `design.status` edit arriving over the websocket while a preview banner is up. Expected: the banner replaces its proposal (same id → no change; new id → new descriptions), no second banner. Pinned in Task 5.

**Interfaces (Produces):**
- `Button({ kind?: 'primary'|'quiet'|'danger'; disabled?; busy?; onClick; children; type?; 'data-testid'? })` — 44 px min height; `busy` shows a 16 px spinner and disables.
- `IconButton({ label: string; icon: VNode; onClick; disabled?; pressed?; 'data-testid'? })` — 44×44, `aria-label`, `aria-pressed` when `pressed` defined.

- `Stepper({ value: string; placeholder?; onCommit(value: string | null); step?: number; disabled?; label; 'data-testid'? })` and pure `stepValue(value: string, delta: number): string` (uses Task 3's `parseLength` moved here: `parseLength(value): { number: number; unit: string } | null` and `formatLength`): "−"/"+" buttons commit `stepValue(value, ∓step)` immediately; typing commits on Enter/blur; empty commits `null`; an unparsable value disables −/+ and keeps the text editable.
- `ColorField({ value: string; placeholder?; onCommit(value: string | null); disabled?; label })` and pure `isLiteralColor(value): boolean` (`#hex` 3/4/6/8, `rgb[a](…)`, `hsl[a](…)`, CSS named colors list); shows a swatch with the literal color, a neutral swatch otherwise; a native `<input type="color">` behind the swatch for literal hex values commits on change; text commits on Enter/blur.
- `Toggle({ checked: boolean; onChange(checked: boolean); label; disabled? })` — `role="switch"`.
- `Sheet({ open: boolean; side: 'right'|'bottom'; width?: number; maxHeight?: string; onClose; label; children })` — panel with a drag handle on the bottom variant; `open=false` renders nothing.
- `Modal({ open; title; onClose; children })` — backdrop, Escape closes, `role="dialog"`.
- `Toast` + `useToasts(): { toasts: ToastItem[]; push(t: { kind: 'ok'|'error'|'info'; text: string; sticky?: boolean; action?: { label: string; run(): void } }): number; dismiss(id: number): void }` and `ToastStack({ toasts; onDismiss })`; non-sticky toasts auto-dismiss after 4000 ms (injectable `now`/timer for tests).
- `Menu({ label; items: { label: string; run(): void; disabled? }[] })` — overflow menu button with a popover list; closes on choice, Escape or outside tap.
